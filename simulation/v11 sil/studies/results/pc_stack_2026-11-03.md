# PC robot-stack regression — November 3, 2026

The current arm robot was tested on the desktop PC, with ROS 2 Jazzy in Ubuntu-24.04 WSL and MuJoCo/firmware SIL.
No Pi, physical robot, firmware flashing, or paused real-camera bench was used. Runs used the normal `~/omni_ws`,
ROS domain 73, the full navigation profile, firmware protocol 5/build `90817150`, seed 0, and the existing house map.
Arm runs had six toys, `clutter:=toys`, no walking person, and no viewer/face display. Browser checks used the
catch/base `robot` step with a walking person, no clutter, and its default simulated clock.

Arrival error is distance from the requested world goal to simulator truth, not localization error. These are single
scenario checks. The arm implementations/cameras used different clock modes; their elapsed times are **not** a controlled
camera or implementation performance comparison. The simulator generally ran below real time (roughly 0.5–0.8× while
other tests ran); this does not qualify a physical computer, real sensors, microphone recognition, or CAD clearances.

## Issues corrected

- **Console killed during takeover of an external launch.** The supervisor's old broad stop invoked `omni.sh stop`,
  whose process-name matching could kill the supervisor through its own `omni_console` web-directory argument.
  Simulation takeover now validates launch argument tokens, snapshots that launch's descendants, sends SIGINT to
  the launch, and escalates only to remaining recorded processes. PID start times prevent signalling a reused PID;
  unrelated processes and the console survive. A regression covers a reparented child, a misleading detector line,
  and an unrelated process in the same process group. The live takeover is also exercised in this session.
  Owned sessions use the same process-tree cleanup: previously a second SIGINT could interrupt the mission node's
  cleanup and leave a separately grouped SLAM child. A dedicated regression verifies that owned children cannot
  remain orphaned. The clean final browser run had exactly one SLAM node throughout its inspected transitions.
- **Inactive SLAM hidden by cached TF.** A lost lifecycle configure reply could leave slam_toolbox inactive. The
  console kept its old `map -> odom` transform and treated it as a live localizer, preventing its restart watchdog.
  Map switches now invalidate the old transform and reject queued older samples; a stale map transform falls back
  to odom. The console queries lifecycle state when fresh map TF is missing, completes configure/activate if needed,
  and measures the watchdog interval from the last fresh map frame. SLAM gets a lifecycle shutdown before SIGINT,
  and the mission node ignores a second SIGINT during its bounded child cleanup.
- **Tidy harness budget and reporting.** The old 240 s wall budget stopped an initial D435 tidy at 2/6 binned.
  `arm_load.py` now exposes `--tidy-timeout` (600 s default), records start/timeout status, skips picking after failed
  navigation, waits for a timed-out arm to finish stopping, and declines subsequent driving phases if it does not.
  A run that never becomes ready no longer executes its phases.
  Patrol uses a unique test route and deletes it only if this invocation created it; other phases no longer delete
  the fixed `mode load` route.
- **Follow smoke fixture.** After a long route/map session the walker may be away from the intended acquisition
  position. The browser check verifies that the return goal actually arrived and restarts an already-enabled
  simulated person in front of the robot. It does not enable a person in a world configured without one.
  After Explore, the browser check now supplies an initial pose on reloading the previous map. Loading otherwise
  deliberately assumes the map's start. Simulation truth is used only to place this fixture, not by robot control.
- **SIL stop assertion.** The firmware command ramp stayed within its configured limit (~4.24 m/s²); roller/contact
  motion briefly reached 5.19 m/s² over a 50 ms window. The check now asserts the command limit directly at 1 kHz
  and checks physical stopping over 100 ms, retaining the physical stop/disarm assertions and tolerance.
- **Speech test fixture.** This PC's Windows recognizer rejected Zira's synthesized “follow me”, while David's
  complete command was recognized. SAPI output voice can be selected with `OMNI_SAPI_VOICE`; the recognizer test
  fixes its input voice to David without changing the robot's default output voice.
- Firmware-reference tests honor `OMNI_FIRMWARE_DIR` so they work against the mirrored WSL layout as well as the repo.

## Remaining shutdown limitation

The installed composed Nav2 container sometimes segfaults during SIGINT cleanup, or needs the launch's bounded
SIGKILL escalation. This occurred after completed missions. A direct lifecycle shutdown returned success and cleaned
up the managed nodes, but did not eliminate the container exit crash, so that proposed workaround was not retained.
Console takeover now survives and stops the detected process tree. Vendor versions: `nav2-collision-monitor`
1.3.13-1noble.20260921.030324, `rclcpp-components` 28.1.22-1noble.20260911.115213, `slam-toolbox`
2.8.5-1noble.20260915.204151. No vendor libraries were modified. This shutdown issue remains open.

## D435 filtering experiment — rejected

Two in-process SIL probes used the current ARM/D435 robot, the ROS seed-0 six-toy layout, house world, and 400 s sim
limit. Raw depth finished at 244.7 s with 6/6 physically binned (6 task picks, 1 failed candidate). A 3×3 NaN-aware
median before detection reached the limit at 400 s with 5/6 physically binned despite 6 reported picks, 1 failed
candidate and 1 skipped candidate. The filter was **not adopted**. A task pick counter alone is not physical bin
confirmation. Raw depth can still propose floor artifacts; these probes do not validate the full object suite or
navigation through camera-only clutter.

## Reproduction

Use the sim venv for Windows checks and the ROS venv with Jazzy/workspace sourced for WSL tools. Start `omni.sh arm`
directly with the desired `arm_camera:=stereo|d435`, `arm_impl:=py|cpp`, `clock:=sim|wall`, `nav_profile:=full`,
`viewer:=false`, `foxglove:=false`, `web:=false`, `face:=false`, `person:=false`, and `n_objects:=6`.
Then run `ros/tools/arm_load.py <out.json> --phases NAVTIDY,ROUTE --legs 1 --laps 1 --tidy-timeout 600` in the same
ROS domain. For browser checks use the supervisor's `robot` step with `person:=true`, and run
`ros/tools/console_smoke.py --slam --tabs --faults` on Windows. Stop only the corresponding session when switching.

Detailed run records and browser/test output: [pc_stack_2026-11-03.json](pc_stack_2026-11-03.json).

All robot launches, SLAM children, the supervisor and Windows face viewers created for this session were stopped
after verification. The temporary isolated checkout created before Fernando's instruction to use the normal
workspace was removed; the reported behavior runs used `~/omni_ws`.
